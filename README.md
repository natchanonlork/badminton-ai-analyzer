# Badminton AI Analyzer

วิเคราะห์คลิปแบดมินตันจากกล้องตัวเดียว ตามผู้เล่นและลูก แบ่งแรลลี่ จับจังหวะตี เดาประเภทช็อต แล้วสร้างวิดีโอผลลัพธ์

```
คลิป -> setup.json (คลิกจุดคอร์ท+ผู้เล่น) -> TrackNetV3 (ตามลูก) -> bai.analyze -> overlay.mp4 + ตารางข้อมูล
```

## 1. ต้องมีอะไรบ้าง

| สิ่งที่ต้องมี | ใช้ทำอะไร | หมายเหตุ |
|---|---|---|
| Windows + Python 3.11 | รันโปรเจกต์ | ทดสอบบน Windows 10 |
| การ์ดจอ NVIDIA + CUDA | เร่งความเร็ว AI | CPU รันได้แต่ช้ามาก ทดสอบล่าสุดบน RTX 3070 |
| ffmpeg | ตัดและเข้ารหัสวิดีโอ | ต้องเรียก `ffmpeg` จาก terminal ได้ |
| Browser | เปิดหน้า `pick_corners.html` | ทำงานในเครื่อง ไม่อัปโหลดคลิป |
| YOLO11 Pose (`yolo11m-pose.pt`) | หาผู้เล่นและท่าทาง | Ultralytics โหลดให้อัตโนมัติถ้ายังไม่มีไฟล์ |
| TrackNetV3 + checkpoint | ตามลูกแบด | ติดตั้งแยก ดูข้อ 2 |

Library ของ Python: PyTorch, Ultralytics, OpenCV, NumPy, pandas, PyArrow

repo นี้ไม่มีคลิป ผลลัพธ์ และไฟล์โมเดล ต้องเตรียมเอง ส่วนโค้ด TrackNetV3 มากับ submodule

## 2. ติดตั้ง

```bash
git clone --recurse-submodules https://github.com/natchanonlork/badminton-ai-analyzer.git
cd badminton-ai-analyzer
pip install torch --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt
```

TrackNetV3 มาเป็น submodule ที่ `third_party\TrackNetV3` ล็อกไว้ที่ commit ที่ทดสอบแล้ว ถ้า clone มาโดยไม่ใส่ `--recurse-submodules` ให้รัน `git submodule update --init`

ติดตั้ง library ของ TrackNetV3:

```bash
cd third_party\TrackNetV3
python -m venv env
env\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cu121
pip install dash numpy opencv_python pandas Pillow plotly parse tqdm
```

ดาวน์โหลด checkpoint จากลิงก์ใน [README ของ TrackNetV3](https://github.com/qaz812345/TrackNetV3) แล้วแตกไฟล์ให้ได้ `ckpts\TrackNet_best.pt` และ `ckpts\InpaintNet_best.pt`

TrackNetV3 ระบุ `requirements.txt` ไว้สำหรับ Python 3.8 แต่เครื่องที่ใช้งานจริงรันด้วย Python 3.11 และ library รายการด้านบน

## 3. วิธีถ่ายคลิป

ค่าที่โค้ดเตือนโดยตรง:

| หัวข้อ | ค่าที่ควรใช้ |
|---|---|
| แนวภาพ | แนวนอนเท่านั้น คลิปแนวตั้งไม่ผ่าน |
| ความละเอียด | อย่างน้อย 1280x720 แนะนำ 1920x1080 |
| เฟรมเรต | แนะนำ 60 fps ต่ำกว่า 30 ลูกจะเบลอและหายบ่อย |
| ความยาว | เกิน 60 นาทีจะประมวลผลนาน แนะนำตัดเป็นช่วงสั้นก่อน |
| ไฟล์ | เลี่ยงคลิปอัดหน้าจอ เพราะเฟรมเรตไม่คงที่ |

คำแนะนำที่ช่วยให้ทำงานง่าย (มาจากวิธีการทำงานของระบบ ยังไม่ได้ทดลองเปรียบเทียบเป็นตัวเลข):

1. **ตั้งกล้องบนขาตั้งและห้ามขยับ** ระบบใช้ตำแหน่งคอร์ทชุดเดียวทั้งคลิป ถ้ากล้องขยับ ซูม หรือแพน ตำแหน่งจะคลาดทั้งหมด
2. **ตั้งกล้องหลังเส้นหลังคอร์ท กึ่งกลาง และสูง** ให้มองเห็นผู้เล่นฝั่งไกลโดยไม่ถูกตาข่ายหรือผู้เล่นใกล้บัง
3. **ให้เห็นเส้นคอร์ทให้ครบ** อย่างน้อยต้องเห็นจุดอ้างอิง 4 จุด แนะนำ 6 จุดขึ้นไป และเห็นเท้าผู้เล่นทุกคน
4. **ปิดโหมดปรับอัตโนมัติถ้าทำได้** ล็อกโฟกัสและแสง ใช้ชัตเตอร์เร็วเพื่อลดลูกเบลอ
5. **ใช้แสงสม่ำเสมอ** และเลี่ยงฉากหลังสีขาวหรือสว่างจัด เพราะลูกจะกลืนกับฉาก
6. **เริ่มถ่ายก่อนเสิร์ฟเล็กน้อย** และให้มีเฟรมที่ผู้เล่นทุกคนยืนอยู่ในคอร์ท เพื่อใช้คลิกระบุตัว
7. **อย่าให้คนเดินผ่านหน้ากล้อง** และลดคนยืนข้างคอร์ท เพราะอาจถูกจับเป็นผู้เล่น
8. **ตัดคลิปไฮไลต์ที่เปลี่ยนมุมกล้องก่อน** ให้แต่ละคลิปมีมุมเดียว

## 4. ขั้นตอนทำคลิปใหม่

ตัวอย่างใช้คลิปชื่อ `myclip.mp4` เปลี่ยนชื่อและ path ให้ตรงกับเครื่องคุณ

**ขั้นที่ 1: วางคลิป** ไว้ที่ `clips\myclip.mp4` ถ้าคลิปยาวให้ตัดก่อน (ข้อ 7)

**ขั้นที่ 2: สร้าง setup**

```bash
start pick_corners.html
```

1. เลือกคลิป เลือกเดี่ยวหรือคู่ แล้วหยุดที่เฟรมที่เห็นเส้นคอร์ทชัดและผู้เล่นอยู่ในคอร์ทครบ
2. คลิกจุดอ้างอิงบนคอร์ทอย่างน้อย 4 จุด แนะนำ 6 จุดขึ้นไป จุดเน็ตให้คลิกฐานเสาที่แตะพื้น
3. เช็กว่ากรอบสีเขียวทับเส้นจริง ถ้าเหลื่อมให้ลบจุดที่ผิดแล้วคลิกใหม่
4. คลิกที่เท้าผู้เล่นแต่ละคนและพิมพ์ชื่อ
5. กดดาวน์โหลด `setup.json` แล้วย้ายมาไว้ในโฟลเดอร์โปรเจกต์ (ใช้กับ cmd):

```bash
move "%USERPROFILE%\Downloads\setup.json" setup_myclip.json
```

**ขั้นที่ 3: ตามลูก** รันในโฟลเดอร์ `third_party\TrackNetV3` ได้ไฟล์ `clips\myclip_ball.csv`

```bash
env\Scripts\python.exe predict.py --video_file C:/path/to/clips/myclip.mp4 --tracknet_file ckpts/TrackNet_best.pt --inpaintnet_file ckpts/InpaintNet_best.pt --save_dir C:/path/to/clips --large_video
```

- ต้องใส่ `--large_video` เพราะแบบปกติล้มด้วย `MemoryError` เมื่อทดสอบกับคลิป 1080p ยาว 30 วินาที บนเครื่อง RAM 32 GB
- `--video_file` ต้องใช้ `/` ไม่ใช่ `\` ถ้าใช้ `\` โปรแกรมจะไม่สนใจ `--save_dir` และเขียน CSV ไว้ข้างคลิป ซึ่งอาจทับไฟล์เดิมโดยไม่เตือน

**ขั้นที่ 4: วิเคราะห์** รันในโฟลเดอร์โปรเจกต์

```bash
python -m bai.analyze clips\myclip.mp4 --setup setup_myclip.json --shuttle-csv clips\myclip_ball.csv --out out_myclip
```

**ขั้นที่ 5: ดูผล**

```bash
start out_myclip\overlay.mp4
```

## 5. ผลลัพธ์ที่ได้

| ไฟล์ | เนื้อหา |
|---|---|
| `overlay.mp4` | วิดีโอพร้อมผลวิเคราะห์ |
| `analysis.json` | สรุปแรลลี่และสถิติผู้เล่น |
| `shots.csv` | รายการช็อต เวลา คนตี ประเภท |
| `players.csv` / `shuttle.csv` | ตำแหน่งผู้เล่นและลูกรายเฟรม |
| `tracks.parquet` | ตำแหน่งทั้งหมดรวมกัน |
| `hits_debug.csv` | จุดเปลี่ยนทิศของลูกและเหตุผลที่นับหรือไม่นับเป็นการตี |

ระบบเก็บผลบางขั้นไว้ใน `--out` ถ้าแก้แค่ชื่อผู้เล่นให้รันซ้ำได้โดยไม่ต้องตามผู้เล่นใหม่ แต่ถ้า **แก้จุดคอร์ทหรือเปลี่ยนคลิป ต้องใส่ `--force` หรือใช้โฟลเดอร์ `--out` ใหม่** ไม่อย่างนั้นจะใช้ค่าเดิม

## 6. ความเร็วขึ้นอยู่กับอะไร

- **การ์ดจอ:** ปัจจัยใหญ่สุด CPU ช้ากว่ามาก
- **งานอื่นที่ใช้ GPU:** อย่ารัน TrackNetV3 กับ `bai.analyze` พร้อมกัน เพราะจะแย่ง GPU และหน่วยความจำการ์ดจอ
- **จำนวนเฟรม:** เวลาแปรตามความยาวคลิปคูณ fps คลิป 60 fps มีเฟรมเป็น 2 เท่าของ 30 fps
- **ความละเอียด:** คลิปยิ่งใหญ่ยิ่งใช้เวลาอ่าน เข้ารหัส และใช้ RAM มากขึ้น
- **การใช้ผลเดิมซ้ำ:** ถ้าไม่ใส่ `--force` จะไม่ต้องตามผู้เล่นใหม่

ค่าที่วัดได้กับคลิป 1080p 30 fps ยาว 30.8 วินาที (924 เฟรม) บน RTX 3070 RAM 32 GB ไม่มีงานอื่นใช้ GPU วัดรอบเดียว ใช้เป็นแค่ค่าประมาณ:

| ขั้นตอน | เวลา |
|---|---|
| ตามลูก (`predict.py --large_video`) | 7 นาที 6 วินาที |
| วิเคราะห์และสร้างวิดีโอ (`bai.analyze`) | 1 นาที |
| รวม | ราว 8 นาที หรือประมาณ 14 เท่าของความยาวคลิป |

เมื่อรันพร้อมงานอื่นบน GPU ขั้นตามลูกใช้เวลาเพิ่มเป็น 25 นาที

## 7. ตัดคลิป (`bai/cut.py`)

```bash
python -m bai.cut clip match.mp4 --start 1:41 --end 1:53
python -m bai.cut auto match.mp4 --min-sec 8 --top 5
python -m bai.cut scenes match.mp4 --court --min-sec 6
```

- `clip` ตัดช่วงที่ระบุ
- `auto` ตัดช่วงที่เหมาะให้อัตโนมัติ
- `scenes` แสดงช่วงที่เห็นคอร์ทและกล้องนิ่ง

ผลอยู่ในโฟลเดอร์ `clips` ข้างไฟล์ต้นทาง หรือกำหนดเองด้วย `--out-dir` ไม่เขียนทับไฟล์เดิม และคงเสียงไว้ถ้าต้นทางมีเสียง มุมคอร์ทที่คำสั่งนี้พิมพ์เป็นค่าหยาบ ห้ามใช้วิเคราะห์

## 8. ข้อจำกัด

- **ความแม่นวัดจากคลิปเดียว:** คลิป 1080p 30 fps ยาว 30.8 วินาที เทียบกับเฉลยที่ติดป้ายเอง รอบหนึ่งได้จับช็อต 20/21 ผู้ตีถูก 18/20 ประเภทช็อตถูก 13/20 ช็อตเกิน 3 ครั้ง อีกรอบที่คลิกจุดคอร์ทใหม่ได้จับช็อต 19/21 ประเภทถูก 13/19 ช็อตเกิน 4 ครั้ง ผลจึงเปลี่ยนตามจุดที่คลิก กฎถูกปรับจากคลิปนี้เอง ตัวเลขจึงอาจสูงกว่าการใช้กับคลิปใหม่
- **คะแนนผู้ตีต้องใช้ชื่อตรงกับเฉลย:** ถ้าชื่อใน `setup.json` ไม่ตรงกับไฟล์เฉลย `bai.eval_shots` จะนับว่าผู้ตีผิด
- **ประเภทช็อตเป็นการเดาจากกฎ:** กล้องตัวเดียวไม่รู้ความสูงของจุดตี จึงแยก smash, clear, drive ได้ไม่แน่นอน
- **ไม่คำนวณความเร็วลูก:** เพราะวัดจากกล้องตัวเดียวไม่น่าเชื่อถือ
- **ยังไม่รู้ผู้ชนะแรลลี่และเหตุผลที่จบ**
- **กล้องต้องนิ่ง:** ระบบไม่รองรับกล้องที่ขยับ
- **ผู้เล่นฝั่งไกลและคนที่ถูกบัง:** ผลตามตัวอาจขาดช่วงหรือสลับคน
- **TrackNet ที่เขียนเองใน `bai/tracknet.py` ยังไม่ได้ใช้ในขั้นตอนหลัก:** ให้ใช้ TrackNetV3 ผ่าน `--shuttle-csv`
- **การหาคอร์ทอัตโนมัติเป็นแบบพยายามเท่าที่ได้:** ควรใช้ `--setup`

## 9. วัดความแม่นเอง

สร้างไฟล์เฉลย `t_s,hitter,type` แล้วรัน:

```bash
python -m bai.eval_shots out_myclip\shots.csv truth\myclip_shots.csv
```

## 10. ปัญหาที่เจอบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `No such file: setup.json` | ยังไม่ได้ดาวน์โหลดหรือย้ายไฟล์มาไว้ในโฟลเดอร์โปรเจกต์ |
| `ไม่พบไฟล์ clip.mp4` | ใช้ชื่อตัวอย่าง ให้เปลี่ยนเป็น path ของคลิปจริง |
| ไม่มีแรลลี่หรือช็อต | ลืมใส่ `--shuttle-csv` |
| `MemoryError` ตอนรัน `predict.py` | ใส่ `--large_video` |
| ตำแหน่งบนคอร์ทเพี้ยน | คลิกจุดใหม่ให้กรอบเขียวทับเส้นจริง แล้วรันด้วย `--force` |
